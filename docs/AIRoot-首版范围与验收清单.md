# AIRoot 首版范围与验收清单

版本：v1.0（整理稿）  
日期：2026-10-18  
依据：《AIRoot-产品构想与分歧审查》v0.76  
状态：用于后续设计、实现和验收；本文件中的命令是接口草案，尚未实现。暂不编写 Agent SKILL。

## 一、本轮决定与实施顺序

首版保留已讨论的完整产品范围，允许先完成一张表，再完成第二张表。不能把某张表的阶段完成说成完整首版交付，也不将 Node.js、Java、WSL、Docker 等类型排除到首版之外。

本整理稿采用“环境表先做、工具表后做”的实施顺序：工具可能属于某个环境，先建立环境登记与维护能力，再接入工具关系更便于验证。这个先后顺序是整理时采用的工作安排，用户没有逐字指定先做哪张表。

本轮明确：

- 首版需要扫描暂停功能，并提供继续入口；以保存进度后继续作为实施目标。用户主动暂停后不自行恢复。
- 暂不做本地图形界面。用户通过 AI 对话查询，底层必须提供命令或脚本查询能力。
- 真实 Agent 权限联调留到后续，当前规划暂按 Agent 能履行权限职责推进；不能据此声称真实接入已经通过验证。
- 内嵌组件、存储位置和维护可靠性按已定要求安排实现验证。
- SKILL 将来需要，当前仍不编写。

## 二、首版交付划分

| 阶段 | 要完成的内容 | 阶段结束应能做到 |
| --- | --- | --- |
| A：共同基础与环境表 | 信息目录、必装搜索组件、扫描暂停与继续、环境发现与查询、项目关联、环境维护及异常处理 | AI 能查清有哪些环境、在哪里、状态如何，并按既定规则安装或维护环境、同步登记 |
| B：工具表与关联 | 工具发现与查询、版本与调用信息、所属环境、MCP 关联、自制脚本、工具维护及联动 | AI 能找到并调用合适工具，知道所需环境，维护后两张表保持一致 |
| C：首版整体验收 | 两张表联合查询、并发使用保护、恢复、存储隔离、组件生命周期、完整场景验证 | 首版各项承诺有可复现的验证结果；真实 Agent 授权联调结果另列 |

阶段 A 就要设计好可被工具表引用的环境标识和项目关联，避免阶段 B 推倒重做。两张表是两类逻辑登记，不预先限定必须是两个文件或两张数据库表；这些实现选择不影响用户使用方式。

## 三、两张表分别管什么

### 环境表

| 范围 | 首版应处理的内容 | 登记单位说明 |
| --- | --- | --- |
| conda | 发现各个已有环境，查询、核实、创建、补装、升级、删除及登记同步 | 每个实际环境分别登记 |
| venv | 发现各个已有环境，查询、核实、创建、补装、升级、删除及登记同步 | 每个实际环境分别登记 |
| Node.js、Java | 对各已安装运行环境提供发现、查询和适用的维护能力 | 整理建议按实际安装实例区分版本与路径，不把普通项目目录当运行环境 |
| WSL | 纳入发现、登记及适用维护流程，记录与宿主机的关系 | 需要在实现设计时明确平台与发行版如何关联，不能把启用系统能力当作普通文件安装 |
| Docker | 纳入发现、登记及适用维护流程，能区分相关对象及其关系 | 运行时、镜像、容器的登记单位和维护语义需设计，不混为同一种环境，不把数据卷当作可随意清理的环境 |

后面三类的具体对象划分是实现前需具体化的设计项；保留在首版范围内，不代表目前已批准任意系统修改或清理容器数据。各类型应列明支持的操作、必要条件、不适用项和对应验证方式，不能只登记名称就宣称完成全部维护能力。

环境记录建议覆盖：稳定标识、名称、类型、实际位置、运行入口、版本、依赖清单、关联项目、来源、可用状态、最近核实时间及当前使用情况。只记录适用于该类型且能确认的内容，未知就标明未知。

### 工具表

| 范围 | 登记与关联要求 |
| --- | --- |
| ffmpeg、各种 CLI、便携工具及 Blender 等 | 区分实际安装实例，记录版本、位置、准确调用入口及状态 |
| 安装在环境内的工具 | 关联所属环境，删除环境前能识别连带影响 |
| 通过已安装且可用的 MCP 连接器开放操作的软件 | 软件与连接器分别登记并关联；不因为网上存在连接器就自动收录软件 |
| 自制实用脚本 | 能独立调用、完成实用功能且可复用；关联所需环境，缺依赖先记录、按需准备 |

普通软件、普通项目源代码、临时测试脚本不因文件类型或名称相似就自动纳入。CLI 不要求必须有 MCP。

工具记录建议覆盖：稳定标识、名称、版本、实际位置、调用入口、关联环境或连接器、关联项目、来源、可用状态及最近核实时间。工具特有调用方式必须能被查询到；简短用途及最小示例作为补充建议，尚未单独确认，不以此扩大为完整工具说明书维护。

## 四、通过 AI 和命令完成查询

用户可以直接问 AI：

- 这台电脑有哪些 Python 环境？各自对应哪些项目？
- 哪个环境适合继续这个项目？路径是什么？
- ffmpeg 装在哪里？有几个版本？怎么调用？
- 这个工具依赖哪个环境？目前能用吗？
- 扫描到哪里了？还有哪些位置没扫？先暂停。
- 上次安装成功了吗？登记是否完成？
- 哪些资源存在问题？哪些项目可能受影响？

命令或脚本至少要提供以下查询能力。下表命名仅用于说明接口形态，尚不可执行；若最终采用脚本入口，保留同样能力即可。

| 能力 | 命令形式草案 | 应返回的信息 |
| --- | --- | --- |
| 查询环境 | `airoot env list` | 按类型、项目、状态等筛选环境，支持控制返回数量 |
| 查看单个环境 | `airoot env show <id>` | 路径、运行入口、版本、依赖、项目、状态及已知问题 |
| 查询工具 | `airoot tool list` | 按名称、项目、版本、状态等筛选实际工具实例 |
| 查看单个工具 | `airoot tool show <id>` | 调用入口、所属环境、项目关联、连接器关系及状态 |
| 按任务要求找资源 | `airoot resource find` | 先查登记；无匹配时按规则做有限针对性查找，分别说明结果来源与验证状态 |
| 查看项目关联 | `airoot project show <id>` | 当前记录的环境与工具关系，不把历史使用当成仍在依赖的保证 |
| 查看扫描 | `airoot scan status` | 运行或暂停状态、已覆盖和未覆盖范围、跳过原因；无法准确计算总进度时不编造百分比 |
| 查看维护结果 | `airoot operation show <id>` | 实际操作状态、登记状态、相关路径、错误及所需后续行动 |
| 查看维护日志 | `airoot log show <id>` | 对应操作的可用日志；不泄露凭据 |

普通列表与详情查询不安装、不升级、不删除资源。针对性查找可按已定规则核实并补登记，但也不直接安装。查询支持供 Agent 读取的结构化输出，以及便于人读的简短输出；两种输出应描述同一个实际状态。查询只返回与问题有关的内容，避免每次把两张表完整塞给 Agent。

## 五、扫描与维护入口

查询之外还需要以下操作能力；具体参数与风险分类在接口设计中统一，不能只提供查表功能。

| 操作组 | 首版能力 |
| --- | --- |
| 发现与扫描 | 首次本机磁盘全扫、状态查询、暂停、继续、定向补扫、用户指出位置后的补登记 |
| 登记维护 | 核实资源、同步外部新增或移动、补充项目关联、取消登记并忽略、恢复管理 |
| 环境维护 | 创建、补装依赖、升级、删除，各类型按自身实际语义执行并同步登记 |
| 工具维护 | 安装、升级、删除、并存版本管理、所属环境及连接器关联 |
| 使用保护 | 记录任务正在使用的具体资源，冲突维护时阻止修改；任务异常结束后核实再解除对应保护 |
| 信息恢复 | 备份轮换、登记损坏后的有条件自动恢复、登记失败后核实补登记 |

暂停扫描应保存已经完成的工作与进度；已验证结果仍可查询。再次继续时接续处理，并复核中断期间可能变化的对象。进程意外退出后是否自动恢复仍是实现策略待定项，不能把用户主动暂停解释为允许自行恢复。

AIRoot 返回操作风险和必要前提，例如需要明确指定删除对象、需要重启确认、存在使用冲突等；Agent 负责取得授权与沟通。AIRoot 不读取 Agent 的 Full Access 模式。当前按 Agent 能履行这些职责设计，后续真实联调再验证。

## 六、必须延续的产品规则

| 主题 | 首版要求 |
| --- | --- |
| 存储 | 自有登记、配置、日志、索引、进度、备份等全部在用户目录 .airoot；程序与内嵌组件安装位置由用户指定；资源在正常维护位置，不搬迁已有资源 |
| 初始化位置 | 缺少 env、tools 目录时由 Agent 询问位置与是否初始化；空间不足或安装路径例外同样按已定规则确认 |
| 搜索组件 | PET、Everything 及调用接口、fd 随产品装载；内嵌 Everything 独立，不复用外部实例；其自有信息仍遵循 .airoot 约束 |
| 资源复用 | 优先满足要求的项目已有资源；再考虑无需改依赖的其他资源；登记无匹配时先有限查找，明确新建要求除外 |
| 新建环境 | 冲突或无可靠回退方式时新建，以任务简称命名、重名加数字、记录项目；没有明确项目则记录临时任务 |
| 项目与依赖 | 实际使用后追加项目关系，保留原关系；遵循指定依赖版本，在授权范围内调整，不凭猜测改项目要求 |
| 权限 | 普通模式新增安装需求单独确认；Full Access 可直接处理任务所需安装升级，但保留删除、重启、位置变更、付费等已定确认边界 |
| 使用保护 | 使用中的具体实例禁止冲突修改或删除；异常退出不直接等于空闲，无法核实则保留保护 |
| 清理 | 不主动删除旧环境或工具；任务完成后可提示并列出项目及影响，由用户选择；仅本次可确认归属的失败安装残留可自动清理 |
| 失败 | 安装、验证、登记分别如实报告；临时故障按已定范围最多自动重试两次；部分删除不移除未核实对象的登记 |
| 登记失败 | 已安装并验证成功的资源保留；满足权限与使用保护时当前任务可先用；后续核实补登记，不到其他目录偷偷保存信息 |
| 备份恢复 | .airoot 内有限备份；确认损坏、能保留原件且不覆盖新写入时可恢复并告知；不重放旧维护操作或仅凭旧记录解除保护 |
| 日常体验 | 成功简报、异常及时说明、日志按需查；扫描发现问题先记录，任务需要或用户要求时再修复 |
| 卸载 AIRoot | 保留管理的环境和工具，默认保留登记及项目信息；移除自己的嵌入组件与专属索引、启动项，不影响独立 Everything |

本节为摘要，完整边界以构想文档已确认内容为准。Full Access 不代表能够绕过操作系统限制，也不代表所有资源类型都可以用相同命令维护。

## 七、验收场景

以下全部是待执行的验收要求，不是已经通过的测试。阶段 A 的成功不能替代阶段 B 与 C 的验收。

| 编号 | 场景 | 通过标准 | 阶段 |
| --- | --- | --- | --- |
| A01 | 扫描本机已有环境 | 在已知样本上发现并正确区分 conda、venv、Node.js、Java、WSL、Docker 相关对象；说明覆盖范围和无法验证项，未知项目不瞎填 | A |
| A02 | 暂停并继续扫描 | 暂停后进度保存在 .airoot；已核实结果可查；继续时接续处理，不重复制造记录；用户暂停后不自行恢复 | A |
| A03 | 部分目录无权访问 | 继续其他扫描，记录跳过范围和原因，结束后集中告知，不自行修改权限 | A |
| A04 | 项目查询和资源选择 | 查询结果能返回准确路径与状态；优先选择符合需求的项目环境；实际复用后追加关联且保留旧关联 | A |
| A05 | 创建新环境 | 按每类资源适用的创建或安装方式执行，位置和命名符合规则，验证后登记并记录项目；不适用的操作明确说明 | A |
| A06 | 补装与升级 | 不影响旧项目时按授权补装；可能破坏兼容或无可靠回退时采用独立环境方案；指定依赖不擅改 | A |
| A07 | 删除指定环境 | 仅处理明确指定对象；使用中不能删除；核实删除后才移除登记，失败或部分成功保留实际状态 | A，B 补验连带工具 |
| A08 | 漏扫与外部变化 | 用户指出位置后可核实补登记；外部新增可补登记，移动确认同一资源后更新，身份不明时不合并 | A、B |
| B01 | 常用工具查询 | 查到各具体实例的版本、路径、调用入口及状态，按明确版本要求或项目使用记录选择合适实例 | B |
| B02 | 收录范围 | CLI、独立实用脚本、符合规则的 MCP 软件及连接器被正确处理；普通软件和临时项目脚本不误收录 | B |
| B03 | 安装和升级工具 | 成功后验证并登记；可能影响旧项目时保留旧版并存，无法并存则按规则确认 | B |
| B04 | 环境与工具联动 | 删除前列出内部工具和已知受影响外部脚本；成功后清除实际已删实例登记，保留其他副本与外部脚本 | B |
| B05 | 取消登记与恢复管理 | 取消登记不删文件，后续扫描持续忽略同一资源；恢复时核实身份并保留历史备注和项目关系 | B |
| C01 | 全部信息的存储位置 | 检查登记、配置、日志、索引、进度、备份均符合 .airoot 约束；未向环境目录散落 AIRoot 自有信息 | C |
| C02 | 内嵌 Everything 独立性 | 外部 Everything 已安装或未安装时均使用内嵌实例；运行与卸载不干扰外部实例；核对最终组件分发条件 | C |
| C03 | 安装失败与有限重试 | 临时下载故障不超出两次自动重试和原授权范围；失败记录保留，残留清理不触及旧资源或共享文件 | C |
| C04 | 升级失败恢复 | 在支持的维护路径上验证恢复与核实；不能可靠恢复的路径在操作前走新建方案，不事后假称能回退 | C |
| C05 | 安装成功、登记失败 | 报告安装成功与登记未完成及实际路径；不自动卸载重装；只在使用保护有效等条件满足时允许任务先用 | C |
| C06 | 并发任务使用同一资源 | 一个任务使用期间，其他任务不能覆盖、升级或删除该实例；崩溃或断开后先核实再解除对应保护 | C |
| C07 | 信息损坏与恢复 | 保留损坏原件并选有效备份；报告备份时间及可能缺失内容；不覆盖新写入，不回放删除等旧操作 | C |
| C08 | 日志和异常查询 | 简报与查询结果一致；部分成功不报全成功；日志按操作可查，含密钥等内容不被保存或回显 | C |
| C09 | 扫描发现不可用资源 | 标明已知问题或待验证状态，集中提示；没有任务需要或用户要求时不主动修复 | C |
| C10 | 卸载 AIRoot | 仅移除产品自身组件和专属项，受管资源保留，登记信息默认保留；外部 Everything 不受影响 | C |
| L01 | 真实 Agent 普通安装确认 | 未授权或拒绝时不执行，新安装需求不复用旧授权 | 后续联调 |
| L02 | 真实 Agent Full Access 与例外 | 普通任务安装直接执行；删除、重启等仍遵守已有确认边界；占用冲突不被放行 | 后续联调 |
| L03 | AI 对话到命令调用 | AI 按需查询、正确使用路径和状态，维护后继续原任务；不把未完成登记当作成功，不反复全扫 | 后续联调 |

L 类测试按用户本轮要求暂缓，不阻塞当前整理和按假设开发；在实际执行前持续标为未验证，不与脚本模拟混淆。其他验收先通过命令层与受控场景验证；破坏性场景使用专门测试资源，不拿现有用户项目试删。

## 八、后续实现时需要具体化的内容

以下不再逐项进行产品反问，可在设计时提出合理默认值；涉及扩大操作权限或改变已确认边界时仍需明确处理。
